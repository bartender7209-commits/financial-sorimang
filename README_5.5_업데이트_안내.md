# 금융소리망 5.5 — 실시간 상담의 규칙 엔진 병렬 검토

## 핵심 목적
기존 5.3 가입 통제 엔진과 5.4 연구용 개선 분류기를 **같은 직원 상담 발언에서 동시에 실행**하여 판정 차이를 보여줍니다. 5.4 후보의 별도 40문장 정확도는 57.5% → 67.5%로 상승했으나 오탐은 6건 → 7건으로 증가했습니다. 따라서 검증 없이 기존 가입 잠금 로직으로 교체하지 않습니다.

## 이번에 추가한 것
- `index.html` — 기존 상담·가입 통제 UI는 유지하고, `규칙 탐지 엔진 동시 비교` 연구용 패널과 스크립트 연결 추가.
- `live-compare-v55.js` — 화면에 **등록된 직원 발언**에 대해 두 엔진의 위험 표현 탐지 여부를 각각 계산. 판정 불일치 발언을 우선 나열.
- `risk-v54.js` — 기존 5.4 후보 분류기 (수정 없음).
- 다른 동봉 파일 — 5.4 비교 페이지를 아직 업로드하지 않았더라도 한 번에 반영할 수 있도록 포함.

## GitHub 업로드 방법
1. `금융소리망_5.5_실시간_병렬검토_GitHub업데이트.zip`을 압축 해제.
2. GitHub `bartender7209-commits/financial-sorimang`의 `main` 브랜치에서 `Add file → Upload files`로 **ZIP 루트의 파일만** 업로드. `index.html` 같은 기존 파일은 업데이트.
3. `functions/api/records.js`, `engine.js`, `sorimang-db.js`, `cloud-analytics.js` 및 Cloudflare D1 바인딩/비밀키는 **수정하지 않음**.
4. Cloudflare Pages에서 GitHub 커밋의 자동 배포 성공 여부 확인.
5. https://financial-sorimang.pages.dev/ 접속, `홍콩 ELS 문제 상담`과 `정정 표현 비교` 시연을 통해 병렬 검토 결과가 달라지는지 확인.
6. https://financial-sorimang.pages.dev/evaluation-compare.html 의 별도 40문장 비교 화면도 확인.

## 동작과 한계
- 추가 비교 패널은 `#transcript` 안에 등록된 **은행원 발언만** 브라우저 내에서 계산. 고객 발언·음성인식 중 확정되지 않은 임시 텍스트는 포함하지 않음.
- 위험 감지 **건수는 정답과 비교하는 정확도 통계가 아닙니다**. 같은 문장에 여러 위험표현이 있더라도 발언 한 건으로 계산.
- 기존 가입 차단/해제는 여전히 **기존 엔진**이 처리. 후보 분류기는 업무 의사결정을 바꾸지 않음.
- 5.4 평가 데이터 100개는 개발에 참조했으며 40개는 별도 작성 합성 시험. 둘 다 외부 독립 검증이 아니고 실제 은행 상담 STT 성능의 근거가 아님.
- 공개 GitHub 저장소이므로 서버 비밀키, 고객 개인정보/녹음/실제 상담 원문을 코드에 포함하지 말 것.

## 빠른 자가 점검
1. '홍콩 ELS 문제 상담' 실행 → 직원 발언 수 증가, 기존/후보 위험 감지 발언 비교 확인.
2. '전체 초기화' → 병렬 비교 지표 0으로 돌아가는지 확인.
3. '정정 표현 비교' → 부정·정정 문구의 판정 차이 확인.
4. '가상 가입 진행 잠금'은 기존과 동일하게 동작하는지 확인.
5. D1 서버 분석 페이지 조회 및 인증 요구 유지 확인.
