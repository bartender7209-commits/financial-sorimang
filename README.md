# 금융소리망 5.0 · 상담 데이터 분석 1차 개발본

기존 금융소리망 4.0의 음성인식, ELS 설명 항목 10개 점검, 위험 표현 탐지, 가상 가입 차단, TXT 다운로드 기능을 유지하면서 로컬 저장과 분석 대시보드를 추가했습니다.

## 이번 버전에서 작동하는 것

- `index.html`: 기존 상담 모니터링 및 가상 가입 통제, 상담 종료 시 IndexedDB에 자동 저장, `상담 DB 저장` 버튼으로 수동 저장
- `analytics.html`: 10개 설명항목 누락 빈도, 상담별 검토 우선순위, 누적 지표, 개별 상담 기록 및 원문 보기, 검색·필터
- `sorimang-db.js`: 웹 브라우저의 IndexedDB `financial-sorimang-v5-local`에 상담 저장·조회·삭제
- `engine.js`: 기존 4.0 체크리스트 엔진을 대시보드의 가상 샘플 분석에도 재사용
- `analytics.js`: 대시보드 표시, CSV/JSON 백업, 합성 시연 24건 생성 기능

## 중요한 한계 (대회 제출 시 반드시 설명)

1. **서버 DB가 아닙니다.** 각 사용자의 같은 브라우저·같은 도메인 내부에 저장됩니다. 다른 컴퓨터·다른 도메인으로 자동 공유되지 않습니다. 캐시·사이트 데이터 삭제, 시크릿 모드 종료 등에 따라 없어질 수 있습니다.
2. **실제 고객 정보를 입력하지 마세요.** 브라우저 음성인식 서비스는 외부 음성 처리 서버를 사용할 수 있습니다. 이 버전은 가상 상담·교육·경진대회 시연용입니다.
3. **AI 위험 예측·법규 위반 판정이 아닙니다.** 상담 텍스트의 규칙 기반 검사 및 휴리스틱 점수입니다. `검토 우선순위 = MIN(100, 미확인 항목 수×6 + 미해소 위험 알림 수×18 + 질문 알림 수×8)`은 발표용 지표이며 실증 검증된 위험도 확률이 아닙니다.
4. `합성 시연 데이터 생성`은 실제 상담 관측값이 아닌 가상 샘플이며, 학습·검증 데이터셋 또는 실제 AI 정확도 통계로 인용해서는 안 됩니다.
5. 기존 음성인식은 Chromium 브라우저 지원 및 사용자 마이크 권한이 필요합니다. 직접 입력과 내장 시나리오는 마이크 없이 가능합니다.

## Cloudflare Pages + GitHub에 배포

1. **기존 GitHub 저장소 `financial-sorimang`의 현재 코드를 보존**하세요. GitHub에서 커밋 기록을 유지하면 이전 버전으로 복원할 수 있습니다. 편의를 위해 별도 브랜치 `v5-dev`에서 먼저 작업하는 것도 좋습니다.
2. 이 폴더의 **5개 파일 전체**(`index.html`, `analytics.html`, `sorimang-db.js`, `engine.js`, `analytics.js`)를 GitHub 저장소 최상단에 올립니다. `README.md`도 같이 올려도 됩니다.
3. GitHub에 `main` 브랜치에 커밋하면 연결된 Cloudflare Pages가 자동 재배포합니다. 테스트만 하려면 별도 브랜치로 먼저 커밋하고 Preview 주소를 확인하세요.
4. 기존 `https://financial-sorimang.pages.dev/`에서 상담을 진행한 뒤 `상담 종료·최종 점검`을 누르세요.
5. `https://financial-sorimang.pages.dev/analytics.html`에서 저장된 상담 기록과 분석을 확인하세요.
6. 대회 시연용 통계를 바로 보고 싶다면 ‘합성 시연 데이터 생성’을 누르세요. 합성 데이터임을 반드시 명시합니다.

## 점검 흐름

- `홍콩 ELS 문제 상담` → 시연 종료 → `상담 데이터 분석` → 위험 우선순위 및 발언 기록 조회
- `정상 ELS 상담 시연` → 시연 종료 → 분석 화면에서 상대적 경고 차이 확인
- `상담 DB 저장`으로 진행 중 기록을 수동 저장할 수 있습니다.
- `TXT 다운로드`와 `요약 CSV`, `JSON 백업`은 서로 다른 기능입니다. JSON에는 발언 원문이 포함됩니다.
- 분석 데이터는 브라우저 단위 저장이므로 대회 발표에 사용할 컴퓨터에서 미리 시연 기록을 준비하세요.

## 다음 단계 제안

공용 서버 DB가 필요한 경우 Supabase Auth + Row Level Security(RLS)로 접근권한을 설정하고, 시연 전용 익명 식별자·최소한의 분석 메타데이터부터 수집하는 방식이 바람직합니다. 별도의 보안설계·사용자 동의 없이 실제 상담 원문을 공개 DB에 저장하면 안 됩니다.
